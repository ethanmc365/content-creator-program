# Moving the platform to Tryp.com infrastructure

A runbook for whoever moves the Creator Platform off the current Supabase
project (`heuhqqoxyggawuckxocp`, eu-central-2, Pro org, Micro compute) and Vercel
team onto Tryp.com-owned accounts or servers. Written 13 Oct 2026 against the
live system; numbers below are from that day.

## 0. Pick the route first

| Route | What changes | Effort | Downtime |
| --- | --- | --- | --- |
| **A. Transfer ownership** of the Supabase project, Vercel project and GitHub repo into Tryp.com organisations | Nothing in the code. Billing and access move. | Hours | None |
| **B. New Supabase project** (Supabase Cloud under Tryp, or self-hosted Supabase on Tryp AWS) | Copy schema, data, files, functions, secrets; repoint the app | Days | A short write freeze (about an hour) |
| C. Rewrite onto a different backend | Most of the product logic is in Postgres functions and policies, so it would be a rebuild | Months | n/a |

Recommendation: **A first** (it is reversible and buys time), **B** when Tryp
needs the data on its own servers. C is not recommended. The rest of this
document is route B, except section 11, which lists what changes in either case.

A step-by-step guide to giving the new owner access (route A, done by the
current owner) is kept outside the repo; ask Ethan for it.

## 1. What has to move

| Thing | Size (13 Oct 2026) | How it moves |
| --- | --- | --- |
| Postgres `public` schema | 136 tables, ~540 functions, ~200 triggers, ~310 policies | `pg_dump` (schema), see 3 |
| Postgres data | ~120 MB | `pg_dump` (data), see 4 |
| `private` schema | `private.config` (settings + secrets) | dump, then edit the URLs, see 6 |
| Auth users | ~270 accounts with password hashes | `auth` schema data in the dump; passwords keep working |
| Storage files | 532 MB, 2,972 files in 7 buckets (14 Oct) | `node scripts/backup-storage.mjs`, then upload, see 5 |
| Edge functions | 12 (`supabase/functions/`) | `supabase functions deploy`, see 7 |
| Scheduled jobs | ~30 pg_cron jobs | recreate from `supabase/schema/platform.sql` |
| Realtime publication | 16 tables | in `platform.sql`; re-add with `alter publication supabase_realtime add table ...` |
| App hosting | Vercel project + env vars + `vercel.json` headers | Vercel transfer or new project |

`supabase/schema/` is a readable snapshot of everything in the database,
regenerated by `node scripts/schema-snapshot.mjs`. Use it to check the copy:
run the script against the new project (`PROJECT_REF=<new>`) and diff.

## 2. Before you start

1. Freeze schema changes. Refresh `supabase/schema/` and commit.
2. Get the database password for the old project (dashboard > Database) so
   `pg_dump` can connect. Use the **session pooler** or direct connection, not
   the transaction pooler.
3. Create the new project in the **same region family** (EU) on Postgres 17,
   with the extensions in `platform.sql` enabled: `pg_cron`, `pg_net`,
   `pg_stat_statements`, `pgcrypto`, `uuid-ossp`, `supabase_vault`. On the new
   project create `pg_net` in the `extensions` schema (the old project has it in
   `public`, which the advisor flags; it cannot be moved in place without
   dropping in-flight webhook calls, and its functions live in schema `net`
   either way, so no function needs changing).

## 3. Schema

```bash
pg_dump "$OLD_DB_URL" --schema-only --no-owner --no-privileges \
  --schema=public --schema=private > schema.sql
psql "$NEW_DB_URL" -f schema.sql
```

Then re-apply what a schema dump does not carry or what Supabase manages:

- **Grants.** Run `select public.lock_down_definer_functions();` once: it grants
  every definer function to `authenticated` (or locks it to the owner) by the
  rules in `public_rpc_allowlist` / `owner_only_rpcs`. Table grants for
  `anon`/`authenticated`/`service_role` follow Supabase defaults.
- **Event trigger** `no_new_function_is_public` (keeps those grants right on
  every new function): recreate it, see `triggers.sql` (bottom).
- **Role settings** (not in a dump):
  ```sql
  alter role authenticator set session_preload_libraries = 'supautils, safeupdate';
  alter role authenticator set statement_timeout = '8s';
  alter role authenticator set lock_timeout = '8s';
  alter role authenticated set statement_timeout = '8s';
  alter role anon set statement_timeout = '3s';
  ```
  `safeupdate` matters: some functions are written assuming it (bare
  `delete`/`update` must have a `where`).
- **API pool sizes** (set 13 Oct 2026 on the old project after a connection
  crunch): PostgREST `db_pool = 12`, Auth `db_max_pool_size = 5`. Size them to
  the new instance.

## 4. Data

```bash
pg_dump "$OLD_DB_URL" --data-only --no-owner --disable-triggers \
  --schema=public --schema=private --schema=auth > data.sql
psql "$NEW_DB_URL" -f data.sql
```

- `--disable-triggers` matters: loading rows must not fire notifications,
  invoices or scoring a second time.
- `auth` data brings users and password hashes, so everyone can log in with the
  same password. **Everyone is signed out once** (the new project signs tokens
  with a new key), which is fine: the app shows the login screen.
- Skip `cron.job_run_details`, `net._http_response`, `public.ops_stat_snapshots`
  (logs). `public.view_snapshots` and `admin_audit_log` are history; keep them.
- After loading: `select setval(...)` is not needed (all ids are uuids), but run
  `analyze;`.

## 5. Files (Storage)

Buckets: `avatars`, `gallery`, `chat-media`, `creator-kit`, `resources`,
`video-thumbs` (public) and `dm-media` (PRIVATE). Create them with the same
settings (`platform.sql` lists limits and allowed types), copy the policies on
`storage.objects` (`policies.sql`, schema `storage`), then copy the objects with
the same paths. `node scripts/backup-storage.mjs --out <folder>` downloads
every bucket (read-only, resumable, with a manifest); upload the folder with
`supabase storage cp -r` or the S3-compatible endpoint (`rclone`/`aws s3 sync`).

**Stored URLs contain the old address.** These columns hold absolute URLs that
start with `https://heuhqqoxyggawuckxocp.supabase.co/storage/...` (row counts on
13 Oct): `creator_photos.photo_url` 1,066, `submissions.thumbnail_url` 824,
`profiles.photo_url` 251, `vip_videos.thumbnail_url` 186,
`tracked_videos.thumbnail_url` 55, `submission_disqualifications.snapshot` 52,
`messages.video_url` 22, `flights.photo_url` 14, `messages.image_url` 11,
`submission_duplicates.snapshot` 4, `resources.file_url` 1,
`creator_portfolios.copy` 1. Rewrite them once the files are copied:

```sql
-- example for one column; repeat per column above (jsonb columns: cast to text and back)
update public.profiles
   set photo_url = replace(photo_url, 'https://heuhqqoxyggawuckxocp.supabase.co', 'https://<new-host>')
 where photo_url like 'https://heuhqqoxyggawuckxocp.supabase.co%';
```

Do this with triggers disabled on those tables (or in the same session as
`set session_replication_role = replica`) so no notification fires.

## 6. Database settings that point at the old project

`private.config` holds them. After the data load:

```sql
update private.config set value = 'https://<new-host>/functions/v1' where key = 'edge_functions_base';
-- and re-enter: webhook_secret (must match the edge functions' WEBHOOK_SECRET),
-- youtube_api_key, healthchecks_cron_url, instagram_reels_doc_id
```

Since migration 400 no SQL function contains the project address; they all go
through `public.edge_function_url(name)`. Check with
`select proname from pg_proc where prosrc like '%heuhqqoxyggawuckxocp%'` (should be empty).

## 7. Edge functions

```bash
for f in auth-gate calendar-feed geocode impersonate media-cleanup \
         notify-dispatch push-track send-invoice thumb-cache translate-text \
         upload view-sync; do
  supabase functions deploy "$f" --project-ref <new-ref> --no-verify-jwt
done
```

Set the secrets listed in the README. **Keep the same VAPID key pair**, or every
phone's push subscription stops working until the creator re-enables
notifications. Keep `WEBHOOK_SECRET` equal to `private.config.webhook_secret`.

## 8. Auth settings (dashboard > Authentication)

Site URL and redirect URLs (both app origins), Turnstile captcha (secret key;
the site key is in `src/lib/turnstile.js`), JWT expiry 604800 s (one week),
refresh token reuse/rotation as on the old project, SMTP / email templates,
email confirmation OFF (accounts are approved by the team instead). Google
sign-in is NOT enabled.

## 9. The app (see section 11 for the full list)

- Vercel env: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (new values), redeploy.
- `vercel.json`: the Content-Security-Policy names the Supabase host in
  `connect-src`, `img-src`, `media-src`. Replace it.
- `public/sw.js` needs nothing: the build writes `VITE_SUPABASE_URL` into
  `dist/sw.js` (`vite-sw-env.js`).
- GitHub: set the repository variables `VITE_SUPABASE_URL`,
  `VITE_SUPABASE_ANON_KEY`, `SUPABASE_PROJECT_REF` and the secrets
  `VITE_SUPABASE_ANON_KEY`, `SUPABASE_ACCESS_TOKEN`, `SUPABASE_DB_URL`. The
  workflows default to the old project until then.
- Scripts take `VITE_SUPABASE_URL` from `.env` and `PROJECT_REF` from the
  environment.
- Calendar subscriptions: creators who subscribed to their calendar feed have
  the old `.../functions/v1/calendar-feed?token=...` URL in their phone. Keep
  the old project's `calendar-feed` running for a few weeks, or tell them to
  re-subscribe from Calendar > Subscribe.

## 10. Cut-over order

1. Announce a short maintenance window. Turn on read-only if needed (pause the
   crons on the old project: `update cron.job set active = false`).
2. Final data dump + load (4), files sync (5), URL rewrite (5), config (6).
3. Deploy edge functions (7), recreate crons (from `platform.sql`), check
   `ops-health-check` shows nothing on the admin desk.
4. Switch Vercel env + CSP + `sw.js`, deploy.
5. Smoke test: log in as a creator and an admin, open a room, send a DM with a
   photo, submit a test entry on a test challenge, open VIP, receive a push.
6. Keep the old project paused (not deleted) for 30 days as the rollback.

**Rollback:** point Vercel env back at the old project and redeploy. Anything
written to the new project in between has to be copied back by hand, so keep
the window short.
